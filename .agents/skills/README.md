# Workbench Skills

This workbench-owned README is the provenance registry for skills in this folder. Keep one entry per skill here, outside the imported skill's own files. Preserve upstream READMEs and licenses; do not replace or append provenance to them.

A fork is an imported skill that CAD-Pilot has taken over and maintains as first-party code. Its entry keeps the source repository, revision, import date, license and attribution, adds the fork date and reason, and replaces the update procedure with how first-party changes are checked. Keep the license file with the forked files.

For imported instructions, prompts, and agent definitions, use the README at the corresponding collection folder, following the same convention. Record:

- Source repository URL and source path.
- Immutable commit or release revision and import date.
- License and preserved attribution/license-file location.
- Imported scope and a list of local modifications.
- A review and validation procedure for future updates.

Do not import unlicensed content, strip notices, copy an entire unrelated skill collection, or silently refresh from a moving branch. Record original authorship instead of a third-party source for customizations written in this repository.

The workbench's skills are discoverable here. External design projects need an explicit installation of the selected skills or another supported discovery mechanism; merely mentioning a path does not register a skill with an agent host.

- Scope: the CAD skill, supporting CLI packages, reference material and agent metadata. Other top-level skills were not imported.
- Local changes: at the fork, removed the bundled browser viewer (`cad/explorer/`, with its npm lock and local registry-metadata patches), the workbench check that drove it, and `scripts/render`, whose headless renders loaded three.js from that viewer's packages (the maintained Explorer's `explorer.mjs capture` and `render`, drawn by its background renderer, replace them), dropped `playwright` and `pillow` (both used only by `scripts/render`) and `vtk` (imported nowhere; OCP comes from the no-VTK build) from `requirements.txt`, and rewrote `SKILL.md`, `agents/openai.yaml` and `references/` to route viewing and images to the maintained CAD Explorer through the visual-review skill. Modeling, generation and CLI inspection guidance is retained. Checkouts that installed the old viewer keep its Git-ignored `node_modules` and build output under `cad/explorer/`; delete that folder once it holds only ignored files. `scripts/step` still writes the hidden `.<name>.step.glb` beside each STEP because `scripts/inspect` reads `@cad` topology from it. `scripts/step` checks the solids of each generated part (`scripts/common/solid_check.py`) and warns, without blocking the outputs, about loose faces, open shells, inside-out solids and solids that `common.geometry.is_sound` rejects. The kernel check runs in a worker process on a binary copy of the unique solids, retries a solid it cannot finish on the STEP read back, gives each solid 10 s and each generated part 30 s in all (`CAD_SOLID_CHECK_TIME_SCALE` stretches both; the workbench's end-to-end tests use 4), and is skipped with `--no-solid-check`; see `references/step-generation.md`. Python runtime dependencies are declared in CAD-Pilot's `pyproject.toml` and resolved separately in each machine's Git-ignored `uv.lock` using its configured feeds; exact Python dependency versions are not pinned across machines. `scripts/dxf/render_payload.py`, a DXF preview-payload builder that nothing in the workbench called, was removed with its test. The tools accept native paths: `--output` is read as the platform's path, and sidecar, generator and assembly paths (`common/paths.py`) take either separator, with a root, a drive such as `D:/x` or a UNC share counted as absolute; forward slashes are no longer required on Windows.
- Guidance refresh (2026-10-22): `SKILL.md` and `references/` no longer give default wall, fillet or clearance-hole dimensions or an "ask only when impossible" rule; unknown fit-relevant values are asked about or recorded as provisional assumptions. Added reference-image and technical-drawing guidance, build123d placement, fillet-edge, loft, Boolean, signed-volume and seam pitfalls, the limits of the one-axis `inspect mate`/`measure` results, Python checks on the saved STEP for clearance and overlap, per-check reporting, and self-review captures in a separate Explorer review setup. Removed `assets/design-brief-template.md`, which nothing referenced and which duplicated the brief format in `references/natural-language-specs.md`. Version-specific build123d behaviour was checked on build123d 0.13 before it was written down; upstream notes about build123d 0.10/0.11 failures that did not reproduce on 0.13 were left out.
- Adopted upstream guidance: ideas from https://github.com/earthtojake/text-to-cad release 0.7.26, revision `2f793659fb7bab537e2f00836e06448fc4087cb2`, files `skills/cad/SKILL.md` and `skills/cad/references/` `cad-brief.md`, `build123d-modeling.md`, `positioning.md`, `inspection-and-validation.md`, `repair-loop.md` and `snapshot-review.md`, reviewed 2026-10-22. License: MIT, Copyright (c) 2026 Thompson Labs LLC. The ideas were rewritten for this fork's `scripts/inspect` CLI, build123d scripts and the maintained Explorer; upstream's `cadgen` commands, decorators and snapshot renderer were not adopted. Individual sentences stay close to upstream wording in these sections: `SKILL.md` Required workflow step 3 and Non-negotiables; `references/natural-language-specs.md` opening paragraph, Goal, Reference images and Technical drawings; `references/build123d-modeling.md` Fillet and chamfer edges, Lofts and sampled profiles, Booleans and Validity, volume and seams; `references/positioning.md` Joints or explicit transforms; `references/inspection-and-validation.md` Python checks on the saved STEP and Reporting checks; and `references/rendering-and-explorer.md` Self-review.
- Python API patch (2026-09-22): first-party compatibility changes to `cad/scripts/common/step_scene.py`, `glb_mesh_payload.py`, `threemf.py` and the corresponding `common/tests/test_glb.py`, `test_threemf.py` and `test_step_scene.py` adapt native collection imports, topology casts and gap-preserving bounding-box corner accessors to the OCP 8 API used by build123d 0.13. `common/tests/test_assembly_export.py` checks named occurrences, local placements and actual world bounds instead of assuming exporter-specific hierarchy depths. Assemblies regenerated with build123d 0.13 can have flatter hierarchies and different `@cad` occurrence paths; re-inspect the regenerated artifact and its sidecars rather than translating old IDs. Existing artifact files are not rewritten by this patch.
- Project integration and design checks (2026-10-31), first-party: one generator loader (`scripts/common/generator_module.py`) replaces the two in `generation.py` and `assembly_spec.py`; it puts the generator's folder, the design root and the root's `src/` first on the import path while the generator loads and runs, drops modules previously imported from those folders (the tools' own and the interpreter's excepted), and compiles the generator and the project modules it imports from source (cached bytecode is matched only on whole-second mtime and size) without the loader's own `__future__` imports, so each load reads the project afresh, and a module the interpreter lacks is a one-line `scripts/step` error that points to the project's own environment. `scripts/inspect` indexes any STEP it has no current sidecar for into a per-user cache (`scripts/common/cache.py`, `CAD_PILOT_CACHE`), named by content hash and an index version bumped with the indexer, so the `missing_glb`, `stale_step_topology` and `cad_ref_mismatch` errors and their regenerate hints are gone; `@cad` paths may be absolute or start with `../` for STEPs outside the design root and are reported root-relative inside it. Unlabelled placed parts get fallback occurrence names after their group (`scripts/common/part_names.py`) with one warning, while definitions and the root keep only the user's labels, so identical copies still share one definition and the file's name is never a group. The selector-topology warning is shown only when `scripts/inspect` handed out face or edge refs for the build being replaced (`scripts/common/issued_refs.py`). New `inspect parts`, `inspect hygiene` (`scripts/common/hygiene.py`) and `inspect clearance` with generator-declared `gen_poses()` (`scripts/common/clearance.py`, `scripts/common/step_parts.py`), on one command table in `inspect_refs/cli.py`, which reports any failure as an error payload with exit status 2. `step_parts.label_pattern` and `clearance.OVERLAP_TOLERANCE_MM3` are the homes for CAD Explorer's assembly matching and overlap tolerance. The `--mesh-tolerance` guidance and help now say the flags only refine meshes.
- Upstream imports (2026-10-22): selected fixes and helpers copied from https://github.com/earthtojake/text-to-cad at `2f793659fb7bab537e2f00836e06448fc4087cb2` (v0.7.26), under its MIT License, "Copyright (c) 2026 Thompson Labs LLC" (the same terms as `cad/LICENSE`, whose notice reads "Thompson Labs"). That release moved the shared code into the `cadgen` package, which caps build123d below 0.12 and OCP below 8, so it is not a dependency. Source paths are relative to `packages/cadgen/src/cadgen/` unless they start with `tests/`. Copied pieces and local changes:
  - `step_export.py` lines 110-341, the definition-tree writer in `_create_bin_xcaf_doc` (upstream commits `557db3b16`, `0837ee163`, `ff226ac53`, `3cdedc508`), into `scripts/common/step_export.py`: each placed copy of a shared solid keeps its own name, colour and placement, Part leaves no longer gain a `SOLID` level, a placed root does not add a STEP group, and bare Compound leaves are coloured. Kept build123d's colour semantics (`Color.wrapped`) instead of cadgen's colour contract, dropped per-face colours, and simplified the location helpers. Local changes: colours go on leaf definitions and leaf occurrences only, because STEPCAF writes a coloured sub-assembly occurrence as a presentation with an empty item list (build123d already passes a group's colour to its children); and copies of one solid get a separate definition per label as well as per colour, so each product is named after its own copy rather than the last one, while same-label copies still share one. build123d 0.13's `_create_xde` was compared and not delegated to: it names copies and colours them, but writes a placed root as an extra STEP group, so the file and the in-memory scene disagree. Regenerated models can therefore have different `@cad` occurrence paths: Part leaves lose their `SOLID` level, and for a placed root the old `o1.1` (the extra group) now resolves to the first leaf; `references/inspection-and-validation.md` tells agents to re-inspect rather than reuse saved paths. The one-line `557db3b16` fix also names leaf definitions in `scripts/common/assembly_export.py`. Tests: `common/tests/test_step_export.py` (the placed-root case adapted from `tests/python/packages/cadgen/test_step_export_placement.py`) and the leaf-product test in `test_assembly_export.py`, adapted from `557db3b16`.
  - `_internal/step_scene.py` `_label_name` guard (`a38c383a3`), into `scripts/common/step_scene.py`: checks `IsAttribute` before `FindAttribute`, which segfaults on an unnamed label on OCP 8 too. Its test runs in a child process.
  - Selector-manifest `entryKind` and the inspect reader's fallback to the index manifest (`a5da51d5b`; upstream `packages/cadpy/src/cadpy/glb.py` and `skills/cad/scripts/inspect/inspect_refs/inspect.py` at that commit), into `scripts/common/glb.py` and `scripts/inspect/inspect_refs/inspect.py`, with tests adapted from `tests/python/skills/cad/cadpy/test_glb_topology.py` and `test_refs_inspect.py`.

Local changes: `DEFAULT_MATERIAL` is written in linear RGB so the default still displays `#F4F4F5`, and `URDF_MATERIALS` colours, authored like hex colours, are converted from sRGB to linear in `scripts/common/generation.py` so the GLB and 3MF show them as authored. Expected colours in `test_threemf.py` follow upstream's.

It writes through a symlinked output to the file it names and keeps the previous file's permission bits; a hard link to the previous file keeps the old contents. The teacup's handle bends no tighter than about a 4.9 mm radius, against its profile's 3 mm inner offset, and both of its ends are set into the wall, so it is a sound solid and its meshes are checked like the others. - Print handoff (2026-10-31): first-party `scripts/print`, built from the print writers and slice checks four design projects had each written for themselves. It writes Bambu Studio project 3MFs with named plates from a personal print profile, checks parts in their print orientation, slices with Bambu Studio's command line and writes fit-coupon ladders; see `references/print.md`. No Bambu Studio code or presets are copied: it reads the installed app's system presets and runs its command line when used. `scripts/common/threemf.py` now exposes its mesh, component and package writers for it, and writes the package's content types and relationships with a default namespace instead of an `ns0:` prefix, which Bambu Studio's reader cannot resolve. The orientation checks use SciPy, now a declared dependency. Job-file paths read through `common/paths.py` like the other sidecar paths, and command-line paths like `scripts/step --output`.

### Update Procedure

CAD-Pilot changes this skill directly; there is no upstream refresh. Keep `cad/LICENSE` and the attribution above with the files, and record notable changes under Local changes. From the workbench root, run `node tools/check.mjs`, which covers sample geometry, direct `scripts/step`/`scripts/inspect` generation and inspection, and every test under `cad/scripts` (the `scripts/print` tests that need Bambu Studio skip when the app is not installed). For Python dependency/API changes, also resolve afresh through the configured feeds. For guidance changes, check that viewing still routes to the maintained Explorer through the visual-review skill and that `@cad[...]` references stay with `scripts/inspect`. To adopt a later change from either upstream, review its license and diff, copy only what is needed and record its source revision here. Default print values are not measured calibration or manufacturing certification.
